# 비용 모델과 실측

2026-10-15 기준. law-watch `main@31bcf1e`, 질의 84건(평가·CLI·슬랙) 실측을 단가표로 다시 계산한 값이다.

## 요약

| 경로 | 언제 | 질문당 비용 (중앙값 / 상위 10% / 최대) | 응답 시간 (중앙값 / 상위 10%) |
| --- | --- | --- | --- |
| 되묻기·거절 | 범위가 넓거나 답할 수 없는 질문 | **$0.0003** | 1~2초 |
| 빠른 답 (haiku-5-5) | 값·목록·화면 방식처럼 한두 곳만 보면 되는 질문 | **$0.0031** / $0.0041 / $0.0060 | 12.7초 / 17.1초 |
| 심층 탐색 (sonnet-5-5) | 정책·흐름·설계 배경처럼 여러 레이어를 따라가는 질문 | **$0.046** / $0.081 / $0.120 | 16.1초 / 31.8초 |
| 와이어프레임 (sonnet-5-5) | 새 기능·화면의 화면 초안 요청 | **약 $0.10** (실측 1건) | 약 37초 |

- 질문 하나가 $0.005 미만인 건 **빠른 답 경로뿐**이다. 심층 탐색은 그 15배 안팎이다.
- 질문 하나의 상한은 $0.50이다(`ASKCODE_AGENT_MAX_BUDGET_USD`). 실측 최대는 $0.12였다.

## 계산 방법

비용은 SDK 보고값이 아니라 **토큰 × 공식 단가**로 계산한다(`src/askcode/llm/pricing.py`). 토큰 수는 Console 로그와 정확히 일치하지만, Agent SDK의 `total_cost_usd`는 같은 토큰을 공식 단가로 계산한 값보다 작게 나왔기 때문이다(sonnet-5-5 약 15% 낮음).

| 모델 | 입력 | 출력 | 캐시 쓰기 (입력 × 1.25) | 캐시 읽기 (입력 × 0.1) |
| --- | --- | --- | --- | --- |
| claude-haiku-5-5 | $0.10 | $0.50 | $0.125 | $0.01 |
| claude-sonnet-5-5 | $2.00 | $10.00 | $2.50 | $0.20 |

(USD / 100만 토큰)

질문 하나의 비용은 다음과 같이 구성된다.

```
스코핑(haiku, thinking 끔)          ≈ 입력 1,850 · 출력 200 토큰 → $0.0003
+ 에이전트(빠른 답 또는 심층 탐색)  = 모델 호출 여러 번의 토큰 합계 × 단가
```

에이전트는 도구를 쓸 때마다 모델을 다시 호출한다(중앙값 7회, 최대 17회). 호출할 때마다 이전 대화가 다시 입력되지만, 프롬프트 캐시가 이를 받아 준다.

### 실측 예시: "앱 하단 탭에는 어떤 메뉴들이 있어요?" (빠른 답)

| 항목 | 토큰 | 비용 |
| --- | --- | --- |
| 캐시 읽기 | 33,109 | $0.00033 |
| 캐시 쓰기 | 13,554 | $0.00169 |
| 출력 | 1,062 | $0.00053 |
| 스코핑 | 약 2,050 | $0.00028 |
| **합계** | | **$0.0029** |

## 비용이 어디에 쓰이나

| 경로 | 캐시 쓰기 | 출력 | 캐시 읽기 | 새 입력 |
| --- | --- | --- | --- | --- |
| 심층 탐색 | 41% | 34% | 25% | 0% |
| 빠른 답 | 44% | 36% | 20% | 0% |

- 캐시 재사용률은 심층 탐색 87%, 빠른 답 71%다. 캐시가 없었다면 입력 비용이 약 10배였다.
- 가장 큰 항목은 **캐시 쓰기**다. 매 호출에서 새로 들어온 도구 결과(읽은 코드)가 캐시에 기록되기 때문이다. `read_code`가 돌려주는 줄 수(`ASKCODE_READ_MAX_LINES`)와 턴 수를 줄이면 비용이 줄지만, 정답률과 맞바꾸는 일이므로 평가 세트로 측정하며 조정한다.

## 월 비용 추정

기획자 질문 하루 30건 × 22일 = 월 660건 기준.

| 질문 구성 | 질문당 평균 | 월 비용 |
| --- | --- | --- |
| 일상형: 빠른 답 40% · 심층 45% · 되묻기 15% | $0.024 | **약 $16** |
| 골든 세트형: 빠른 답 32% · 심층 61% · 되묻기·거절 7% | $0.031 | **약 $21** |
| 상한 가정: 모두 심층, 상위 10% 비용 | $0.081 | 약 $53 |

평가 비용은 별도다. 골든 세트 28문항 1회에 판정까지 포함해 **약 $0.85**가 든다.

## 상한과 최악의 경우

- 에이전트는 호출할 때마다 누적 비용을 확인하고, $0.50을 넘으면 멈춘다. 이때 답변 대신 "탐색 한도에 도달했어요. 질문을 좁혀 주세요"를 보낸다.
- 정확히 $0.50에서 끊기지는 않는다.
  - 상한 확인은 호출이 끝난 뒤에 하므로, 마지막 1회분만큼 넘을 수 있다.
  - SDK가 상한 판단에 쓰는 자체 비용 계산이 실제보다 약 15% 낮다. sonnet 기준 실제 상한은 약 $0.58이다.
  - 빠른 답이 실패해 심층 탐색으로 넘어가면 두 실행에 상한이 각각 적용된다. 이론상 최대는 약 $1.1이다.
- 턴 상한은 빠른 답 8회, 심층 탐색 12회다.

## 모델과 effort

| 단계 | 모델 | effort / thinking | 판단 |
| --- | --- | --- | --- |
| 스코핑·스크린샷 문구 추출 | haiku-5-5 | thinking 끔 | 적절. thinking을 켜면 JSON이 잘렸다(400토큰을 thinking이 소진). |
| 빠른 답 | haiku-5-5 | 기본(medium), adaptive | 적절. 중앙값 $0.003·13초, 2차 평가에서 빠른 답 경로 6문항 모두 정답. |
| 심층 탐색 | sonnet-5-5 | 기본(high), adaptive | 정답률은 충분(2차 86%). **effort medium 실험을 권장**한다. |
| 평가 판정 | sonnet-5-5 | 기본 | 적절. haiku 판정은 이유와 결론이 모순되는 경우가 잦았다. |

- **opus-5-5로 올리지 않는 이유:** 단가가 2배이고, 남은 실패 원인이 노션 미연결과 검색 단계라 모델을 올려도 효과가 작다.
- **sonnet-5-5 effort medium 실험:** 다단계 도구 사용에는 medium부터 시작하라는 것이 모델 가이드다. 출력·thinking 토큰이 줄어 비용과 시간이 줄 것으로 기대한다. 실험 방법은 다음과 같다.

```bash
ASKCODE_AGENT_EFFORT_LARGE=medium uv run askcode eval --ids q02,q03,q06,q07,q08,q09,q10,q13,q14,q15,q17,q18,q19,q21,q22,q23
```

  - 2차 평가에서 심층 탐색이었던 16문항이다. 예상 비용은 약 $0.6이다.
  - 정답률이 유지되고 비용·시간이 줄면 `.env`에 `ASKCODE_AGENT_EFFORT_LARGE=medium`을 고정한다.
- effort를 비워 두면 모델 기본값이 적용된다. 다만 Agent SDK가 Claude Code의 기본값을 쓸 가능성이 있으므로, 운영에서는 값을 명시하는 것을 권장한다.

## 한계

- 캐시 쓰기는 5분 TTL 단가(× 1.25)로 계산한다. SDK가 1시간 캐시(× 2)를 쓰면 그만큼 낮게 잡힌다. 그래서 표시는 "비용 약"이다.
- 스코핑 토큰은 질의 기록에 저장하지 않는다. 비용에는 포함되며, 위 표는 Console 평균값으로 추정했다.
- 정확한 청구액은 Console의 **분석 → 비용**이 기준이다.
