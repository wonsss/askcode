# 로직 흐름도

기획자가 정책·흐름을 물으면("매일 받기로 설정하면 푸시가 언제 와요? 조건을 알려줘"), AskCode는 답변과 함께 **조건 분기 흐름도**를 HTML 파일로 스레드에 올린다. 노드마다 근거 코드 위치(`파일:줄`)가 붙는다. 모델은 짧은 **흐름 명세(JSON)**만 내고, 렌더러가 회색조 SVG로 그린다. 와이어프레임의 "명세 + 결정적 렌더러" 방식을 그대로 썼다([wireframe.md](wireframe.md)).

![슬랙에서 받은 흐름도](screenshots/flowchart-slack.webp)

위 화면은 "푸시가 발송 대기 중일 때 사용자가 알림을 끄거나 이미 읽으면 어떻게 돼요?"를 슬랙에 물은 결과다(2026-10-15, `main@31bcf1e`, 확신도 높음, $0.069·16초).
- 오른쪽 스레드: 결론 한 줄과 조건별 목록(알림 끔·이미 읽음·팔로우 해제·기기 로그인 상태·조용한 시간), 개발자 참고, "🧭 흐름도를 올렸어요" 안내, 근거, 그리고 `flow-….html` 파일
- 왼쪽: 슬랙이 그 파일을 연 미리보기. 노드 9개로 "발송 대기 중인 푸시"에서 시작해 조건 4개(기기·로그인 연결 → 수신 빈도 → 팔로우 알림 → 알림함 안 읽음)를 차례로 거친다. 하나라도 "아니오"면 오른쪽 통로로 돌아 **취소되고 발송 안 함**에 모인다. 마지막으로 조용한 시간인지에 따라 **푸시 발송**과 **보류 후 나중에 재확인**으로 갈린다.
- 그림 아래 표: 번호별 단계와 근거 `파일:줄`. 근거는 `mobile-push-policy.ts`(조건)와 `mobile-push-delivery.service.ts`(발송·취소·보류)로 나뉜다.
- 여러 조건이 같은 결과로 모이는 이런 모양 때문에 "두 층 이상 건너뛰는 화살표는 바깥 통로로" 배치를 넣었다. 넣기 전에는 화살표가 중간 조건 노드를 가로질렀다.

## 언제 붙나

| 조건 | 결과 |
| --- | --- |
| 스코핑 kind가 `policy` 또는 `multi_hop` | 질문 뒤에 흐름 명세 지시를 붙인다 |
| 답에서 결과를 가르는 조건이 2개 이상 | 모델이 ```` ```flow ```` 블록을 낸다(필수) |
| 조건이 1개 이하, 또는 `simple`·`screen_hybrid` 등 다른 kind | 흐름도 없음 |
| 명세가 없거나 깨짐, 갈래가 나뉘는 노드가 없음 | 흐름도 없이 답변만 보낸다 |
| 확신도 낮음(검증된 근거 없음), 탐색 한도 도달 | 흐름도를 올리지 않는다 |

- 지시는 시스템 프롬프트가 아니라 **질문 메시지 뒤**에 붙인다. 시스템 프롬프트가 그대로라서 다른 질문과 프롬프트 캐시를 같이 쓴다.
- 처음에는 "(선택)"이라고 썼는데, 실측 1건째에서 조건 5개짜리 답에도 모델이 명세를 생략했다. 그래서 "조건 2개 이상이면 필수"로 바꿨다.

## 결과물

| 위치 | 내용 |
| --- | --- |
| 스레드 답변 | 기존 답변 그대로 + "🧭 흐름도를 올렸어요. 조건별 갈래와 근거를 이 스레드의 HTML 파일에서 볼 수 있어요." |
| 스레드 파일 | `flow-<질문>-<id>.html`. 슬랙 미리보기로 바로 열린다 |
| CLI | `uv run askcode ask "…조건을 알려줘"` → `data/diagrams/`에 저장, 경로 출력 |

그림의 생김새:
- 검은 알약 = 시작, 육각형 = 조건, 얇은 상자 = 처리, 굵은 상자 = 사용자가 겪는 결과
- 위에서 아래로 층을 쌓는다. 화살표 라벨은 "예"/"아니오" 또는 짧은 값이다
- 두 층 이상 건너뛰는 화살표(여러 조건이 같은 결과로 모일 때)는 노드를 가로지르지 않게 오른쪽 바깥 통로로 돈다. 위에서 출발할수록 바깥 통로를 써서 통로끼리 교차하지 않는다
- 앞 단계로 되돌아가는 화살표는 점선
- 노드 왼쪽 위 번호 → 그림 아래 표에 단계와 근거 `파일:줄`. 도구로 실제 읽지 않은 구간이면 "(확인 필요)", 근거가 없으면 "근거 없음"

## 동작 방식

```
질문 → 스코핑(haiku): kind=policy | multi_hop
     → 심층 탐색(sonnet, 읽기 전용 도구). 질문 뒤에 흐름 명세 지시
     → 답변 본문 + ```flow 명세 + 근거
     → 명세 추출(본문에서 제거) → 검증·정규화 → 인용 검증
     → 렌더러: 층 배치 → SVG(노드·화살표·라벨) + 근거 표 → HTML(CSP 포함)
        노드 근거는 인덱스에 있고 도구로 본 구간인지 다시 확인해 표시
     → 슬랙: deliver가 답변 갱신 + files_upload_v2로 스레드에 파일 업로드
```

- 코드: `pipeline/flowchart.py`(명세 검증·배치·SVG 렌더러), `pipeline/prompts.py`(`FLOW_INSTRUCTION`, `FLOW_KINDS`), `pipeline/answer.py`(`attachment_kind="flow"`, `_ref_ok`), `slack/app.py`(`deliver`), `cli.py`
- 테스트: `tests/test_flowchart.py`

### 흐름 명세

```json
{"title":"매일 받기 푸시 발송 조건","nodes":[
{"id":"s","type":"start","text":"매일 받기로 설정","ref":"apps/worker/src/notifications/mobile-push-policy.ts:54-69"},
{"id":"d1","type":"decision","text":"오전 9시가 지났나?","ref":"apps/worker/src/notifications/mobile-push-window.ts:64-82"},
{"id":"r1","type":"result","text":"하루 묶음 푸시 도착"},
{"id":"r2","type":"result","text":"대기 또는 발송 안 함"}],
"edges":[{"from":"s","to":"d1"},{"from":"d1","to":"r1","label":"예"},{"from":"d1","to":"r2","label":"아니오"}]}
```

| 필드 | 내용 |
| --- | --- |
| `nodes[].type` | `start` · `decision` · `step` · `result`. 모르는 값은 `step` |
| `nodes[].text` | 25자 안팎의 쉬운 말(80자에서 자름, 4줄 넘으면 …) |
| `nodes[].ref` | 근거 `파일:줄-줄` (선택) |
| `edges[].label` | "예"/"아니오" 또는 짧은 값(20자에서 자름) |

- 첫 노드가 시작점이다. 노드 16개, 엣지 24개에서 자른다. 없는 노드를 가리키는 엣지와 중복 id는 버린다.
- 노드 3개 미만, 엣지 없음, 갈래가 나뉘는 노드(나가는 엣지 2개 이상)가 없으면 그리지 않는다. 프롬프트는 조건 2개 이상일 때 내라고 하지만, 렌더러는 1개까지 받아 준다.

## 보안

- **외부로 보내지 않는다.** Mermaid 렌더링 서비스 같은 외부 렌더러를 쓰지 않는다. 비공개 코드의 로직이 바깥으로 나가지 않는다. 배치와 SVG는 순수 Python으로 계산한다.
- SVG는 **렌더러가 만든 것만** 나간다. 모델이 준 값은 텍스트로만 쓰이며 전부 HTML 이스케이프한다. 좌표·도형·색은 렌더러가 정한다. `url()`·외부 링크·`<foreignObject>`·화살촉 `marker`(참조)도 쓰지 않는다. 화살촉은 다각형으로 직접 그린다.
- CSP는 와이어프레임과 같다(`default-src 'none'; style-src 'unsafe-inline'; img-src data:` …).
- 모델이 직접 쓴 HTML·SVG는 지금처럼 와이어프레임 정제기가 처리한다. 정제기는 `<svg>`를 내용째 지운다. 흐름도 경로는 HTML을 받지 않는다.
- `tests/test_flowchart.py`가 모든 텍스트 필드(제목·노드·라벨·근거)에 넣은 `<script>`·`<img onerror>`·`<foreignObject>`가 이스케이프되는지 확인한다.

## 비용과 시간 (2026-10-15 실측)

질문 "매일 받기로 설정하면 푸시가 언제 와요? 조건을 알려줘", CLI, `main@31bcf1e`.

| | 1건째: 지시 "(선택)" | 2건째: 지시 "필수" |
| --- | --- | --- |
| 흐름도 | 없음(모델이 생략) | 노드 7 · 엣지 9 |
| 비용 | $0.064 (캐시 없음) | **$0.047** |
| 시간 | 15.9초 | 15.1초 |
| 모델 호출 | 5회 | 5회 |
| 출력 토큰 | 1,424 | 1,860 |
| 캐시 쓰기 / 읽기 | 17,798 / 24,855 | 8,542 / 33,968 |

- 늘어나는 것은 **출력 토큰 약 450개**(명세 1.2KB)다. 단가로 약 **+$0.0045**, 심층 탐색 중앙값($0.046)의 약 10%다. 같은 질문류의 이전 기록은 출력 1,190~1,460토큰, $0.034~$0.067였다.
- 1건째와 2건째의 비용 차이는 대부분 캐시 쓰기 차이다(1건째는 5분 안에 앞선 질문이 없어 시스템 프롬프트를 새로 썼다). 흐름도 때문이 아니다.
- 시간 증가는 출력 450토큰분, 약 2~4초로 추정한다. 2건째(15.1초)는 이전 기록 범위(11~16초) 안이다.
- 렌더링은 0.1ms 미만이다. HTML은 약 8KB다.
- 슬랙 실측(위 스크린샷, 노드 9 · 엣지 11): $0.069 · 16.0초, 출력 2,046토큰, 캐시 쓰기 17,281(캐시 없음). 이 질문류의 이전 슬랙·CLI 기록(흐름도 없음)은 $0.033였다. 차이의 대부분은 캐시 쓰기($0.043)이고, 출력은 약 +770토큰(+$0.008)이다. 조건이 많은 질문일수록 명세가 길어진다.
- 실측이 3건뿐이라 수치는 대략적이다. 골든 세트에는 흐름도 문항이 없다.

## 한계

- 층 배치는 단순하다(최장 경로 층 + 부모 평균 정렬 한 번). 노드가 많거나 갈래가 얽히면 화살표가 겹칠 수 있다. 노드 4~12개를 전제로 한다.
- 두 층 이상 건너뛰는 화살표는 대상 노드 오른쪽으로 들어간다. 대상이 왼쪽 열이면 같은 층의 오른쪽 노드를 지나갈 수 있다.
- 흐름도 내용은 모델이 정리한 것이다. 노드 근거는 검증하지만, 노드 사이 연결이 코드와 같은지는 사람이 근거를 보고 확인해야 한다.
- 단순 경로(haiku)로 가는 질문에는 붙지 않는다.
